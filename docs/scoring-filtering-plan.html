Bindocracy architecture review

Scoring, filtering, diversity & final ranking

A staged plan for turning the generated library into an auditable candidate funnel—without confusing model confidence with binding affinity, or letting a scorer silently become an optimizer.

Recommendation in one page

Build a scorer layer, not a single score

The right v1 is a cascade of immutable candidate snapshots and separate evaluate, filter, cluster, select, optimize, and rank runs. Raw metrics remain available; every verdict records the exact protocol that produced it.

Use now

  • Mosaic as the first fixed-sequence folding/cofolding driver.
  • Boltz-2 for the broad first structural screen.
  • AF2-multimer or OpenFold3 as a model-family cross-check.
  • ProteinMPNN and ESM-C as separate sequence-compatibility critics.
  • Caliby as a static/ensemble-backbone evaluator first.
  • ESMFold2 only after optimization, as the sealed holdout.

Do not do

  • Do not run every expensive model on every raw candidate.
  • Do not call OpenFold3 “AlphaFold 3”; they are distinct models and weights.
  • Do not let inverse folding rewrite a sequence inside an evaluation run.
  • Do not add raw, differently scaled model outputs into one universal score.
  • Do not call ipTM, ipSAE, PAE, Rosetta energy, or Caliby U a measured affinity.
  • Do not let diversity rescue a candidate that fails minimum quality gates.

The full named-model matrix belongs in the calibration pilot. The production panel should be selected from measured complementarity, failure rate and cost—not from the length of the model list.

The DuckDB schema is already conceptually aligned with the goal: a run can be evaluate, filter, cluster, optimize, or rank; metrics are long-form and tied to evaluator runs; decisions are separate from numeric observations; ranks require a scope. This foundation should be retained.

The execution layer is still generation-only. workflow/Snakefile has a fixed prepare → generate → collect → ingest graph, plan_run() hard-codes RunKind.GENERATE, the manifest assumes every task produces designs, and no run currently has a parent. Calibration must be stratified

FreeBindCraft contributes 89.55% of the library. A random pilot would mostly measure that generator. Balance by generator, length, and native pass/fail status, and report all distributions by source before pooling them.

Existing prototype: useful, but not the production contract

Mosaic’s screen_proposals.py already demonstrates model-agnostic fixed-sequence cofolding. However, its default inverse-fold step changes the proposed sequence, it exposes only ipTM/binder pLDDT/interface PAE, and it immediately sorts by ipTM + pLDDT/100 − interfacePAE/30. The production driver should preserve the raw sequence, emit a richer metric bundle, never rank, and make inverse-fold redesign a separate optimization run.

Naming corrections that matter for provenance

Protenix is “Protein + X”; “Proteinx” should not become a plugin identifier. OpenFold3 is an open reproduction in the AlphaFold3 lineage, not DeepMind AlphaFold 3. If actual AF3 is added later, register it independently as alphafold3_deepmind with its own non-commercial code/weight terms.

Boltz-2 affinity is not the answer for protein binders

The released Boltz-2 affinity head is documented and trained for protein–small-molecule affinity. Its CLI example marks a ligand chain as the affinity binder. Do not apply that value to a protein-binder chain or report it as a PPI Kd. For v1, use cofold confidence, interface geometry, and optional Rosetta/FoldX/PRODIGY-like exploratory features—clearly labelled as proxies, never as measured affinity.

How to use Mosaic for the three inverse/sequence critics

  • ProteinMPNN: already implemented in JAX with vanilla, soluble and antibody weights. Expose raw per-residue likelihood and replicate variability. Sequence recovery is useful but should not be the only statistic.
  • ESM-C: already implemented at 300M/600M/6B. For scoring, return pseudo-log-likelihood and pseudo-perplexity without the optimizer’s clipping transform. Record whether the generator already used ESM-C, because it is then diagnostic rather than independent.
  • Caliby: not currently a Mosaic loss. Use Caliby’s native scorer as a separate evaluator on fixed structures/ensembles. If optimization use is later desired, the safe first experiment is a JAX Potts-energy term over precomputed h,J; a fully dynamic loss would require porting or differentiating through Caliby’s backbone encoder and is a distinct engineering project.

The proposed scoring funnel

00

Freeze a candidate snapshot

Resolve an explicit list of design_id, source run, exact sequence hash, optional source structure artifact and generator metadata. This manifest—not a live SQL query—is what every downstream task consumes.

01

Deterministic, cheap prefilter

Validate canonical amino acids and length; calculate composition, net-charge proxy, hydrophobic fraction/patch proxy, low complexity, longest homopolymer, cysteine count and configurable expression liabilities. Compute ESM-C scores and exact/near sequence clusters. Hard-fail only invalid inputs and campaign-specific forbidden motifs; treat other properties as measured features until calibrated.

02

Primary fixed-sequence structural screen

For every surviving design, predict the binder alone and the target–binder complex with Boltz-2 (or the calibrated fast Protenix path). Use a fixed target MSA, no binder MSA, explicit template policy, at least one seed/sample, and no sequence rewriting. Emit structures plus raw confidence and geometry metrics.

03

Survivor consensus and robustness

On a smaller pool, run multiple seeds/samples and a second model family—prefer AF2-multimer for independence, with OpenFold3 as another view. Summarize median, lower quantile, success fraction and model disagreement. Run ProteinMPNN and Caliby on the same registered backbones/ensembles, scoring the original sequence.

04

Protocol-versioned filtering

Apply interpretable gates to normalized metric names. Missing required metrics fail closed. Store one filter decision per design with threshold, comparator, source metric IDs, aggregation rule and protocol version in reason. Use “at least two model lineages pass” only after the pilot defines what pass means per model.

05

Diversity-aware selection before optimization

Cluster the quality-qualified pool in sequence, binder fold and binding pose spaces. Apply source/length/topology caps and choose representatives by a quality-constrained farthest-point or per-cluster quota policy. Record cluster and selection decisions separately.

06

Optimization creates child designs

Each changed sequence is a new DesignRecord with parent_design_id. MPNN redesign, Caliby-guided sequence changes, and Mosaic gradient optimization are optimize runs—not evaluation side effects.

07

Re-score and open the ESMFold2 holdout

Re-run the required non-held-out panel on optimized children, then evaluate the finalists with ESMFold2 full. No threshold tuning against those holdout results inside the same campaign round. Final ranking uses robust normalized ranks/Pareto fronts plus diversity constraints; raw holdout scores remain visible.

Metric contract and default panel

Use canonical metric names; evaluator identity, checkpoint, seed, MSA/template policy and parameters live on the evaluation run and in metric details. Do not encode a model name into every new canonical metric. Existing generator-native names remain unchanged for backward compatibility.

Replicates and summaries

  • Keep each seed/sample as a metric replicate. Deterministic IDs must include run, design, metric name and replicate.
  • Emit separately named aggregates such as complex_iptm_median and complex_iptm_p10; never overload replicate 0 as both a raw value and an aggregate.
  • Record failed/missing samples. “One excellent result out of five crashes” is not the same as five consistent predictions.
  • Use per-model thresholds or within-protocol percentiles. Raw ipTM values from different model implementations are not guaranteed to be calibrated on one scale.

Filtering versus ranking

A filter establishes minimum evidence; a rank orders an explicitly named pool. Keep both as DecisionRecords in their own runs. A composite may be useful after calibration, but its formula, transforms and missing-value policy belong in the rank decision’s reason JSON. Preserve the Pareto front across foldability, interface confidence, sequence plausibility, robustness and diversity.

Diversity is three spaces, not one percentage

1. Sequence

Global-alignment identity with coverage; nearest-neighbor identity; MMseqs2/CD-HIT-style clusters at protocol-defined thresholds; per-position entropy for fixed-length families; ESM-C embedding distance as optional support.

2. Fold

Binder-backbone TM-score/RMSD clusters using Foldseek or US-align. Align binder-to-binder for topology diversity, separately from confidence. Compare the same state (unbound or bound) consistently.

3. Binding pose

Align targets first, then compare binder placement, interface-contact Jaccard, epitope residues, orientation and hotspot coverage. Two unrelated sequences can still propose the same pose.

Report these pool-level summaries

  • Exact unique count, cluster counts at at least two sequence thresholds, singleton fraction and median nearest-neighbor identity.
  • Effective cluster count, exp(Shannon entropy), so one giant cluster plus many singletons is not mistaken for a balanced library.
  • Fold-cluster count and effective fold count among quality-qualified candidates.
  • Pose-cluster count, effective epitope count and epitope coverage map.
  • Generator/source contribution before and after every gate, length distribution and topology distribution.

Selection rule

First define the eligible set with quality gates. Then select with per-cluster/source caps and greedy farthest-point sampling, breaking ties by a robust quality rank. This prevents 89.55%-dominant FreeBindCraft output—or any single prolific family—from consuming the optimization budget. Store cluster assignments and selected representatives so the policy is reproducible.

Exact sequence uniqueness is already 3,302/3,302, but that says almost nothing about useful diversity. The observed length range is 60–149, so coverage-aware alignment and length/topology strata are essential.

Harness changes required before adding scorer plugins

Least-disruptive design

Keep all seven generation plugins working. Add an evaluator contract alongside ToolPlugin, then generalize planning/manifests around run kind and candidate inputs. Host-side filter/cluster/rank operations can use the same immutable snapshot and serialized ingest boundary.

1. Schema v4: snapshot downstream inputs

The metrics and decisions tables can already refer to designs created by older runs. What is missing is durable membership/provenance for multi-source pools; a single parent_run_id cannot express “evaluate designs from seven generation runs.” Add:

run_dependencies (
  run_id, source_run_id, role,
  PRIMARY KEY (run_id, source_run_id, role)
)

run_candidates (
  run_id, design_id, ordinal,
  sequence_sha256, source_structure_artifact_id,
  PRIMARY KEY (run_id, design_id)
)

Keep parent_run_id for simple one-parent lineage. run_candidates is the exact input snapshot and makes partial/restarted evaluation auditable.

2. Manifest: describe operations, not generated designs

  • Stop hard-coding RunKind.GENERATE in plan_run().
  • Replace generation-only designs_per_task assumptions with generic task items, expected output bundle, run kind and candidate-manifest digest.
  • Define count semantics per kind: for evaluation, n_requested candidates, n_attempted launched, n_produced with a complete required metric bundle, and n_passed left null until a filter run.
  • Archive the driver and digest every runtime-consumed file, model checkpoint, container and target/MSA/template input. For symlinked weights, digest the resolved file.

3. Add a separate EvaluatorPlugin seam

class EvaluatorPlugin(ABC):
    tool: str
    config_type: type[EvaluatorConfig]

    def preflight(self, general, model, candidates): ...
    def evaluation_plan(self, loaded, snapshot) -> EvaluationPlan: ...
    def launch_spec(self, manifest, task_id) -> LaunchSpec: ...
    def collect(self, run_dir, run) -> CollectedRun: ...

An evaluator emits no DesignRecords. Its metrics/artifacts use the evaluation run ID and the existing candidate design IDs. An optimizer has a separate contract and emits child designs.

4. Separate workflows, one single-writer boundary

Initially add workflow/evaluate.smk and host-side operations rather than making the stable generation Snakefile dynamic in one jump:

materialize_candidates
       │
       ├── evaluate[shard=0..N] ── collect_evaluation ── ingest
       │
       ├── filter ── ingest
       ├── cluster ── ingest
       ├── select ── ingest
       └── export_selection

All database writes still pass through the existing serialized db_writer=1 resource. Once this is proven, a campaign-stage index can connect generation, evaluation, selection and optimization DAGs.

5. A first scorer package

Implement src/bindocracy/evaluators/mosaic_fold/ with config, preflight, launch, adapter and driver. The driver should borrow Mosaic’s model factory but:

  • accept a shard of registered design IDs and sequences;
  • run binder-only and/or complex modes explicitly;
  • never inverse-fold or rank;
  • emit append-safe JSONL per design/sample, structures and status;
  • make chain roles explicit and validate target sequence/length;
  • require local MSA/weights and refuse silent server fallback;
  • continue after one malformed candidate and preserve partial output.

6. Policy layer

Add versioned YAML for filter and rank protocols, a metric-definition registry (name, unit, direction, scope, version), scorer lineage tags, and a holdout guard. The guard must reject any workflow that references ESMFold2 metrics in pre-optimization filters or optimization objectives.

Calibration and rollout—after this plan is approved

A

Contract work, no GPU

Schema migration and tests; immutable candidate snapshots; evaluator manifest; mock evaluator; filter/cluster/rank records; holdout guard; generation regression suite.

B

Capability probes

One candidate per installed backend on the target GPU class. Record exact package/checkpoint/container digests, backend, peak memory, runtime, output fields and offline behavior. A help/import check is insufficient.

C

Balanced model-matrix pilot

Use roughly 200–300 candidates: balanced across seven generators and length strata, including every native pass plus random and near-threshold failures. Run all proposed folding models and sequence critics here, with enough replicates to measure variance.

D

Choose the production panel

Compare failure rates, cost/design, metric correlation, model disagreement, source/length bias and ability to enrich native passes. Retain complementary models. Freeze v1 threshold and aggregation protocols before evaluating the full library.

E

Full pre-optimization funnel

Run cheap QC on all 3,302; primary folding on survivors; expensive consensus only on the reduced set; quality gates; three-space diversity selection; export an optimization-ready candidate manifest.

F

Optimization and final holdout

Create child designs, repeat the frozen non-held-out screen, then open ESMFold2 for finalists. Produce a final report with raw metrics, uncertainty, Pareto membership, cluster coverage and provenance.

What the pilot must answer before thresholds are approved

  • Which metrics are stable across seeds and which require 3–5 samples?
  • Does Protenix Mini v0.5 provide a useful cheap filter, or is it too outdated/bias-prone?
  • Does AF2 add independent enrichment beyond Boltz-2/OpenFold3 despite the Mosaic wrapper’s no-MSA behavior?
  • Are MPNN and Caliby scores complementary once normalized per binder residue and backbone state?
  • How much selection changes when quality is summarized by median/worst-tail instead of best-of-N?
  • How many sequence, fold and pose families survive, and what generator families are lost at each gate?

Without wet-lab labels, v1 thresholds are operational heuristics. Preserve continuous values and rejected candidates so future assay data can recalibrate the funnel without rerunning every model.

Acceptance criteria for the implementation

Harness correctness

  • An evaluator ingests metrics for existing designs and creates zero new designs.
  • A multi-generator snapshot is deterministic and survives relocation/recollection.
  • A changed sequence, target, MSA, template, driver, image or resolved weight is detected before launch.
  • Partial shards retain complete candidates and mark failed/missing metrics correctly.
  • Rerunning collection is byte-identical and ingestion is idempotent.
  • All seven existing generation plugins and workflow tests remain green.

Scientific correctness

  • Binder/target chain roles are explicit and tested for each backend.
  • The sequence entering an evaluation is byte-identical to the registered design.
  • Raw replicates, aggregates, failures and units are distinguishable.
  • Model lineage and generator/optimizer overlap are visible.
  • No PPI proxy is named affinity or Kd.
  • ESMFold2 metrics cannot influence pre-optimization selection by configuration.

Tests that must exist

Evaluation-only database bundle; multi-parent candidate pool; duplicate candidate ID; mismatched sequence hash; target-chain swap; missing sample; truncated JSONL; metric replicate uniqueness; filter missing-policy; cluster scope; rank scope; inverse-fold mutation refusal; offline-MSA refusal; ESMFold2 holdout violation; schema v3→v4 migration with existing 3,302-design-style relationships.

Decisions for review before any install or model run

Approve the operation split: fixed-sequence evaluation cannot redesign; redesign is an optimize run that creates child designs.
Approve the v1 bootstrap panel: Boltz-2 primary, AF2-multimer or OpenFold3 consensus, MPNN + ESM-C critics, Caliby evaluator, ESMFold2 final holdout.
Confirm the AF3 choice: treat OpenFold3 as OpenFold3 and omit actual DeepMind AF3 for v1 unless separate authorized weights are intentionally supplied.
Confirm the holdout rule: ESMFold2 full (Sept-2021 cutoff), never Fast/2025-cutoff by silent substitution, and no pre-optimization access.
Confirm the affinity language: v1 reports PPI binding/structure proxies only; no absolute affinity claim.
Approve schema v4: add multi-run dependencies and immutable run-candidate membership before scorer implementation.
Choose optional additions: Chai-1 after v1 calibration if model independence is insufficient; RF3 later when its API stabilizes.

Recommended first implementation slice

Schema/manifest support → mock evaluator → Mosaic fixed-sequence Boltz-2 evaluator → versioned filter → sequence clustering/selection → balanced pilot. This slice proves the end-to-end harness seam before multiplying backends.
